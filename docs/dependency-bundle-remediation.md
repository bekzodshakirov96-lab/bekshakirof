# Dependency and SaaS bundle remediation — 2026-10-20

Local-only follow-up to the accounting audit. No production access, data
migration, commit, push or deployment was performed.

## Dependency changes

The full npm audit initially reported 11 affected packages: 8 moderate, 1 high
and 2 critical. These included transitive paths through Vitest, Drizzle Kit and
Tailwind Typography; they were not eleven unrelated production vulnerabilities.

- Upgrade Vitest 2.1.9 to patched 4.1.12, compatible with the project's Vite 7
  and Node 22 CI. This removes the vulnerable old vite-node/Vite/esbuild and
  tinypool dependency paths.
- Override only `@esbuild-kit/core-utils`'s esbuild to 0.25.12, retaining the
  stable Drizzle Kit and database schema behavior. SQL export and all integration
  tests verify the compatibility of this override.
- Override only Tailwind Typography's selector parser to patched 7.1.6. Both
  application stylesheets build successfully.
- Remove the unused Vite 4/5-only JSX development inspector. Production UI
  features are unaffected.
- Regenerate npm and pnpm locks. Verify the pnpm lock with an offline,
  frozen-lockfile check using the declared pnpm 10.4.1.

Full npm audit and full pnpm audit both report **zero known vulnerabilities**,
including development dependencies. This is registry evidence as of this check,
not a guarantee against undisclosed vulnerabilities.

Primary references:
[Vitest 4 migration](https://v4.vitest.dev/guide/migration.html),
[selector parser advisory](https://github.com/advisories/GHSA-rj75-hqrm-r3gf),
[esbuild advisory](https://github.com/advisories/GHSA-67mh-4wv8-2f99).

## Loading changes

The SaaS checkout uses React lazy imports for 22 existing pages and for the
company dashboard shell. Platform routes no longer load company pages and the
company shell at startup. Route URLs, forms, calculations and authentication
checks are preserved. Suspense keeps navigation visible while changing company
pages and provides a loading indicator; ErrorBoundary handles chunk failures.
PDF and Excel libraries remain loaded only when requested.

Browser verification also exposed an unnecessary tenant `auth.me` request from
the shared language provider on the separate platform server. Platform routes
now keep language in browser storage without calling tenant APIs. Company pages
retain account language synchronization. This fix is in both checkouts.

Reference: [React lazy loading](https://react.dev/reference/react/lazy).

Measurements use emitted JavaScript bytes, not simulated network speed:

Exact current measurements are generated by `npm run check:build` and recorded
in `temp/dependency-bundle-fixes/bundle-after.json` in the SaaS checkout.
The guard traverses transitive static imports, verifies all 22 lazy pages exist,
forbids company pages/export libraries in the platform startup graph, and
enforces 600 KB entry / 800 KB platform-route budgets. It runs in SaaS CI.
Thus moving an eager dependency to a separately named vendor chunk cannot
artificially satisfy the size check.
